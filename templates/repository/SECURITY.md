# Security Policy

## Supported versions

No production versions are currently supported. Update this section when releases exist.

## Reporting

Use GitHub private vulnerability reporting when enabled. Do not open public issues for suspected vulnerabilities. Include affected commit/version, impact, reproduction steps, and safe contact details; never include secrets or unrelated personal data.

## Minimum requirements

- No secrets in source control.
- Least-privilege CI permissions and immutable action pins.
- Validate untrusted inputs and dependencies.
- Document trust boundaries and data handling.
- Add security regression tests for confirmed vulnerabilities.
