# Contributing

1. Read README, requirements, architecture decisions, and threat model.
2. Link changes to a requirement or issue with explicit acceptance criteria.
3. Keep pull requests focused and explain compatibility/security impact.
4. Add tests for changed behavior and update interface contracts when applicable.
5. Update manifest metadata when interfaces, dependencies, maturity, or license change.
6. Do not add secrets, personal data, or content without appropriate rights.
7. Mark unfinished work honestly; do not claim unverified capabilities.
