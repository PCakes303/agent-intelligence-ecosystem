# Compliance Control Model

The control catalogue is a proposed governance baseline. It does not establish that any control is adopted, implemented, effective or independently tested.

## Status lifecycle

- proposed: candidate control only.
- designed: owner-approved design and procedures exist.
- implemented: process or technical control is operating.
- tested: test evidence shows the control behaves as intended for a defined scope.
- evidenced: owner-approved, current and traceable evidence supports operation over a defined period.

A control must not advance merely because its description or test exists in this repository.

## Control record

Each control has a stable ID, family, objective, applicability class, implementation status, accountable owner role, linked legal records, expected evidence and review interval.

## Applicability classes

- universal-governance: portfolio governance baseline, not necessarily a statutory duty.
- conditional-by-law: only applies if the linked law applies to the entity and processing.
- conditional-by-use-case: triggered by a specific product, data, decision or user population.
- voluntary-framework: adopted as voluntary guidance or contractually required.

## Evidence rules

Evidence records must identify the system, control, artifact type, collection time, source URI, SHA-256 digest, retention policy, access class, integrity status and reviewer. A digest only verifies byte consistency; it does not establish truth, completeness, legal sufficiency or compliance. Do not place privileged advice or personal data in the public evidence index.
